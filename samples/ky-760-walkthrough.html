Overview

Ky can now add random jitter to retry delays, so a crowd of clients that failed together no longer retries at the same instant and knocks the server over again.

  1. A new retry.jitter option is off by default and accepts true or a (delay) => number function.
  2. After the backoff delay is computed, true picks a random delay between zero and that value.
  3. A custom function can reshape the delay; non-finite or negative results fall back to the original.
  4. backoffLimit still caps the final value, and a server Retry-After skips jitter entirely.

Randomize the retry delay

01 / 04

The delay calculation in Ky used to return the exponential backoff value directly, so every client that failed at the same moment slept for the same time and retried together. It now passes that value through retry.jitter first: with true it picks Math.random() * retryDelay ("full jitter"); with a function it lets the caller decide.

A custom function's result is only trusted if it is a finite, non-negative number; anything else falls back to the un-jittered delay. The existing backoffLimit cap is applied after jitter, and the earlier Retry-After branch returns before any of this runs.

197197##### retry
198198
199199Type: `object | number`\
200200Default:
201201- `limit`: `2`
202202- `methods`: `get` `put` `head` `delete` `options` `trace`
203203- `statusCodes`: [`408`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/408) [`413`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/413) [`429`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/429) [`500`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/500) [`502`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/502) [`503`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/503) [`504`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/504)
204204- `afterStatusCodes`: [`413`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/413), [`429`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/429), [`503`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/503)
205205- `maxRetryAfter`: `undefined`
206206- `backoffLimit`: `undefined`
207207- `delay`: `attemptCount => 0.3 * (2 ** (attemptCount - 1)) * 1000`
208+- `jitter`: `undefined`
208209
209210An object representing `limit`, `methods`, `statusCodes`, `afterStatusCodes`, and `maxRetryAfter` fields for maximum retry count, allowed methods, allowed status codes, status codes allowed to use the [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) time, and maximum [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) time.
210211
211212If `retry` is a number, it will be used as `limit` and other defaults will remain in place.
212213
213214If the response provides an HTTP status contained in `afterStatusCodes`, Ky will wait until the date, timeout, or timestamp given in the [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) header has passed to retry the request. If `Retry-After` is missing, the non-standard [`RateLimit-Reset`](https://www.ietf.org/archive/id/draft-polli-ratelimit-headers-05.html#section-3.3) header is used in its place as a fallback. If the provided status code is not in the list, the [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) header will be ignored.
214215
215216If `maxRetryAfter` is set to `undefined`, it will use `options.timeout`. If [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) header is greater than `maxRetryAfter`, it will use `maxRetryAfter`.
216217
217218The `backoffLimit` option is the upper limit of the delay per retry in milliseconds.
218219To clamp the delay, set `backoffLimit` to 1000, for example.
219220By default, the delay is calculated with `0.3 * (2 ** (attemptCount - 1)) * 1000`. The delay increases exponentially.
220221
221222The `delay` option can be used to change how the delay between retries is calculated. The function receives one parameter, the attempt count, starting at `1`.
222223
224+The `jitter` option adds random jitter to retry delays to prevent thundering herd problems. When many clients retry simultaneously (e.g., after hitting a rate limit), they can overwhelm the server again. Jitter adds randomness to break this synchronization. Set to `true` to use full jitter, which randomizes the delay between 0 and the computed delay. Alternatively, pass a function to implement custom jitter strategies.
225+
226+**Note:** Jitter is not applied when the server provides a `Retry-After` header, as the server's explicit timing should be respected.
227+
223228Retries are not triggered following a [timeout](#timeout).

226231import ky from 'ky';
227232
228233const json = await ky('https://example.com', {
229234 retry: {

231236 methods: ['get'],
232237 statusCodes: [413],
233238 backoffLimit: 3000
234239 }
235240}).json();
236241```

252+

254+ // jitter: delay => delay * (0.8 + Math.random() * 0.4)

256280###### hooks.beforeRequest

619643### ky.stop

619643### ky.stop
620644
621645A `Symbol` that can be returned by a `beforeRetry` hook to stop the retry. This will also short circuit the remaining `beforeRetry` hooks.
622646
623647Note: Returning this symbol makes Ky abort and return with an `undefined` response. Be sure to check for a response before accessing any properties on it or use [optional chaining](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Optional_chaining). 637661 }
638662 }
639663 ]
640664 }
641665};
